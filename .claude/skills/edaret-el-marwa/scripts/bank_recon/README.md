# محرّك المطابقة البنكية اليومية — اكتشاف الفروق فقط (قراءة فقط)

**ممنوع** على هذا المحرّك إنشاء أي قيد أو plug أو مطابقة في أودو؛ يقرأ ويُبلّغ بالفروق فقط.

## ترتيب التشغيل (من مجلد عمل، يحتاج `odoo_client.py` في `/tmp/claude-0`)
1. `python3 list_cands.py` — يحصر مرفقات PDF على القيود (`account.move`) منذ أبريل.
2. (الحصر يُخزَّن في `cands.json` → اجعل `uniq.json` بإزالة تكرار الاسم+الحجم.)
3. `python3 dl.py` — ينزّل الكشوف بالتوازي إلى `dl/`.
4. `python3 parse_all.py` — يقرأ الكشوف (QIB وQNB) ويحدّد الحساب من رقمه داخل الكشف → `parsed.json`.
   تحقّق: آخر رصيد جارٍ = رصيد الإقفال المطبوع لكل كشف (صفر استثناءات).
5. `python3 analyze.py` — يبني سلاسل الأرصدة ويسحب دفتر أودو → `analysis_raw.json`.
6. `python3 compare2.py` — المطابقة (مباشرة / توقيت ±5 أيام / تجميع / محتملة ≤15 يوم) ومعادلة التفسير → `compare2.json`.
7. `python3 build_xlsx.py` — ملف Excel (6 أوراق). تقرير PDF بأسلوب سولفكس يُبنى بقالب المهارة.

> شغّل بـ `python3` عاديًا (لا `-I`) لأن السكربتات تستورد بعضها محليًا. المدخلات المنزَّلة (PDF) تُقرأ بـ pdftotext فقط ولا تُنفَّذ.

## ما يجب الانتباه إليه
- الحساب يُحدَّد من **محتوى** الكشف (رقم الحساب) لا من اسم الملف أو الـ journal.
- معادلة التفسير: الفرق الكلي = افتتاحي (B0) + فروق الفترات + فروق الفجوات — يجب أن تجمع بالمليم (تحقّق ناجح في الحسابات الـ12).
- `ANCHOR` في compare2: QIB يبدأ فعليًا 2026-05-07 (قيد الافتتاح 981,746.58)؛ غيره = أول قيد على الحساب.
- المطابقة بالمبلغ والتاريخ لا بالمرجع؛ قيود uid 62 المتطابقة تُعدّ وتُذكر.
- التقرير الكبير (>3.5MB HTML) يُرسَم جزأين ثم يُدمج (`pdfunite` + `stamp_pagenums.py`) وإلا قد تُقتطع صفحاته الأخيرة.
